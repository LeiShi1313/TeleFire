# Use a standalone Zvec memory module

User memory will be owned by a standalone, platform-neutral module backed by Zvec, not by Telefire. A shared HTTP service is the primary integration and sole Zvec writer, while the same Python core remains directly usable for tests and isolated single-client deployments. The module exposes three subject-scoped operations (ingest observations, augment a request with memory context, and revise memory) while hiding extraction, embeddings, retrieval, profile synthesis, and lifecycle policy; Telefire is only one memory client. Each ingestion targets exactly one subject and one scope and treats its single text payload as authored by that subject; clients submit separate observations for separate people rather than passing multi-participant conversations into the module. Ingestion is a synchronous module operation that extracts structured facts and episodes, suppresses exact retries, persists new records, and returns its result; it does not resolve semantic conflicts or replace existing records automatically. The original observation text is retained with a module-generated identifier for audit and re-extraction, but is excluded from normal augmentation results. Each subject profile is one Zvec record whose content is Markdown text; no separate Markdown file is maintained. Corrections and forgetting use a natural-language revision instruction with optional evidence; the module resolves the affected records so clients do not exchange internal memory IDs. In v1, forgetting removes derived memory from augmentation but does not purge retained observations, and no hard-delete API is exposed. Model calls use a directly configured OpenAI-compatible client for chat completions and embeddings, plus private JSON validation where structured extraction is needed; v1 has no provider registry, model gateway service, or public LLM abstraction. V1 also has no durable ingestion queue, so clients keep ingestion outside latency-sensitive response paths when needed. Telefire submits only human messages used by an AI conversation, one observation per author and message, after the answer path; it does not monitor ordinary chat traffic for memory. It requests scoped memory context for the requester and unique human participants in the bounded reply chain, with one shared prompt budget; stored AI answers and control commands are excluded from participant lookup and ingestion. Memory is optional augmentation: retrieval and ingestion failures are logged and do not prevent Telefire from answering an AI request. Canonical subject and scope keys remain the only identities used by memory records. Clients may separately upsert optional display names into a small generic registry beside Zvec so inspection tools can be readable without depending on Telegram or creating synthetic observations. This replaces Mem0 because the expanded portable domain requires custom episode, subject, scope, and context-packing behavior that would sit above Mem0 anyway, and rejects TencentDB Agent Memory as a runtime dependency because its Node gateway remains coupled to Hermes/OpenClaw and does not provide the required multi-user lifecycle interface.
