# Use Hindsight for contextual memory

Telefire will use Hindsight as the standalone, client-neutral contextual memory engine. This is the selected architecture, not one branch of a fallback design. Hindsight owns extracted facts, experiences, entities, associative relationships, observations, temporal state, source chunks, recall, and memory reflection. Telefire remains one client and provides only the trusted integration boundary: scope selection, stable platform identities, episode serialization, access policy, bounded read tools, prompt assembly, and user-facing correction controls. Telefire will not maintain a parallel assertion graph, alias table, or second memory engine.

Each chat, workspace, or equivalent trust boundary maps to exactly one Hindsight bank. Trusted application code fixes the bank before the answer agent runs; the model cannot name, enumerate, or broaden banks. Private chats, Saved Messages, groups, and future clients remain separate unless an explicit application operation imports evidence into another scope. Tags may organize or filter memories inside a bank, but they are not the isolation boundary.

Every successful `/ai` request may capture its bounded human reply path and current prompt without a chat-level enablement prerequisite. Continuous capture and scheduled Dream are independent, owner-controlled scope settings. Continuous capture ingests eligible settled messages arriving after enablement; Dream performs bounded periodic scans. Continuous capture overrides Dream when both settings are enabled. These settings are independent from AI request authorization and must not reintroduce an AI allowed-chat gate. An explicit owner `/ai_memory` operation is always a one-shot write and does not silently enable either background mode.

The portable ingestion unit is an ordered episode or observation bundle, not one author-owned fact. It preserves stable actor IDs, current display names, replies and quotations, explicit mentions, event and message times, attachment descriptions, optional source references, and source authorship. The adapter must preserve speaker versus described subject, self-report versus third-party claim, event versus mention time, quotation, hearsay, joke, uncertainty, negation, intention, promise, completion, cancellation, and relationship direction. Hindsight may derive memories from this evidence, but an inference used in an answer does not automatically become stored truth.

Every eligible human message can enter memory; replying is not an ingestion requirement. A message with no `reply_to` starts a one-message thread document and may later become the root of a larger document. A reply is assigned to the root of its bounded reply chain so Hindsight can extract with conversational context. Transport batching and thread grouping improve efficiency and coreference resolution, but they do not decide whether a message is memorable.

Four capture paths feed one idempotent episode pipeline. After a successful `/ai` request, Telefire captures the bounded human reply thread and current prompt unless continuous capture already owns delivery for that scope. An owner `/ai_memory` captures its full bounded reply chain, forwarded source, or pasted source-link result in bulk. Continuous capture advances from a durable Telegram message cursor and ingests new eligible messages. A scheduled Dream cycle scans every Dream-enabled Telegram scope over its configured time window. Both background modes assign replies to their roots, retain standalone messages, and submit document updates asynchronously. Hindsight remains platform-neutral and performs memory extraction and observation consolidation after retain.

Every normalized source event carries an optional integration event ID and content version or hash. Telefire maintains ingestion receipts and a per-scope successful scan watermark, which are delivery state rather than a parallel memory model. A stable Hindsight document ID is derived from the scope and reply root; for a standalone message, its own event ID is the root. `/ai`, `/ai_memory`, retries, overlapping dream windows, and later replies therefore converge on the same document. Exact versions are no-ops; any changed structured Episode is submitted as one complete idempotent replacement because Hindsight 0.8.4 append does not merge top-level Episode objects safely. The watermark advances only after every update in the fixed scan interval is accepted successfully. Oversized windows or threads fail visibly without advancing, while bounded overlap and settlement delay catch retries, edits, late replies, and messages arriving during a slow run. Multiple document updates may share one retain request, so transport batching does not require one extraction call per raw message.

Every AI request performs one bank-scoped `recall` using the prompt, reply context, deterministic participants, and explicit references. The answer agent may receive one low- or mid-budget `reflect` operation when resolving an implicit identity, reconciling temporal changes, or following a relevant relationship requires memory reasoning. Source chunks are fetched only for memories used in the answer. The available interface is restricted to bank-pinned read operations equivalent to `memory_recall`, `memory_reflect`, and `memory_get_sources`; bank IDs, write operations, deletion, result limits, token budgets, and call counts are absent or fixed by the host. Normal memory ingestion remains application-driven and outside the answer agent.

The intended experience is evidence-backed continuity: remember current commitments, understand what changed, relate a small number of relevant people, projects, places, objects, events, and shared terms, and communicate when a connection is only possible rather than established. Low-stakes preferences, skills, plans, decisions, shared achievements, and established group lore may be recalled naturally. Rumors and third-party claims remain attributed; sensitive material is reactive-only; insults, harassment, speculative relationships, one-off sarcasm, inferred personality traits, and instructions embedded in retained text do not become unqualified memory.

Explicit Revision uses Hindsight's reversible memory curation instead of a separate profile or suppression store. Telefire first retains the correction evidence, then performs one bank-pinned structured reflection to select candidate world or experience memory IDs. Every selected ID must be present in the reflection's cited `based_on` memories and must pass trusted subject and scope checks before Telefire applies Hindsight's `invalidated` curation state. Invalidated memories remain auditable but are excluded from recall, consolidation, and graph maintenance; a newer retained statement supplies the corrected current evidence. A forget instruction uses the same reversible invalidation path. Telefire does not use bank directives for personal corrections and does not expose hard deletion in this version.

This supersedes the subject-scoped Zvec design in ADR 0002. Existing Zvec data is a migration source and evaluation baseline, not a runtime fallback. Migration re-ingests retained evidence through Hindsight and re-embeds it with the pinned embedding model; existing vectors are not copied. Adoption is gated by behavioral tests for aliases, implicit and multi-step relationships, changing plans, attributed contradictions, attachment-derived group lore, ambiguity, and strict scope isolation.
