# Use a knowledge directory for bounded cross-bank retrieval

A fixed Primary Bank preserves isolation but cannot answer natural questions about knowledge held by another chat, channel, workspace, or non-chat source. Hard-coded aliases and permanently attached banks would make source discovery client-specific, require manual maintenance, and load irrelevant memory into every request. Hindsight banks are isolated and do not natively traverse one another, so cross-bank discovery and authorization must remain application-controlled.

The deployment will have one platform-neutral Knowledge Directory Bank shared by Telegram, QQ, and future adapters. It contains ordinary Hindsight memory describing available knowledge sources, their names, descriptions, and relationships. It is routing knowledge, not an alias table, access-control list, or general world-knowledge bank. Reusable subject matter belongs in independently ingested Shared Knowledge Banks that the directory may describe.

An owner creates a Directory Publication explicitly with `/ai_directory`. One publication describes exactly one adapter-resolved source and carries exactly one trusted, machine-readable Bank Reference. It may use deterministic source metadata plus an optional owner description, but never samples or recalls the referenced bank. Publications are additive evidence; corrections are new evidence rather than silent replacement. Publishing idempotently ensures the referenced bank exists but does not enable capture, Dream, or backfill. Every derived directory fact or observation is isolated to that one reference through matching metadata, an internal reference tag, and a single-reference observation scope.

Each Agent Run automatically recalls the Primary Bank and the requester's filtered view of the Knowledge Directory Bank. The owner may discover every published source. A Whitelisted User may always recall the Primary Bank but directory results expose only that bank and banks covered by an explicit Bank Grant. A Bank Grant is deployment-wide for one exact `(platform-qualified actor identity, target bank)` pair. Telegram and QQ identities are not inferred to represent the same person. Revoking AI whitelist access deletes that actor's grants.

An owner grant command may use an adapter-native source selector only when command and source are on the same platform, such as a Telegram username or QQ group number. A cross-platform source must be selected by its full canonical bank ID. Trusted host code validates grant selectors against a Directory Publication. Names, mentions, and raw IDs in ordinary AI prompt text have no authority. Revocation is fail-safe: once the adapter resolves the source, deleting the stored grant does not require the publication or memory service to remain available.

After filtered directory evidence passes policy validation, the host gives the agent an opaque, run-scoped Bank Capability rather than a bank ID. The agent may explicitly query that capability with a reformulated question. Only validated directory evidence can mint capabilities; text returned by a Consulted Bank cannot directly authorize another bank. A run may consult at most two non-primary banks and perform at most one additional filtered directory lookup. Ambiguity causes clarification rather than fan-out, except when the user explicitly requests comparison or combination. Missing grants, cycles, and exhausted budgets stop traversal.

Requester policy is recomputed for every continuation. Hidden Participant Access Context may advise the model about relevant participants' access, but only the current requester's grants control tools. As recorded in ADR 0004, v1 accepts that a shared persisted Pi session may still contain evidence fetched by an earlier requester with broader access; advisory prompts and current-call enforcement are not a confidentiality boundary. The session dashboard must expose retrieval paths, grant decisions, capabilities, queries, tool results, and this access warning without revealing canonical bank IDs in normal chat answers.

If directory recall is unavailable, ordinary requests may continue with chat context and the Primary Bank, while cross-bank capability issuance fails closed. Explicit requests for an unavailable external source must not be answered as though that source was consulted.

This design preserves bank isolation and client-neutral ingestion while enabling natural source discovery and relationship-driven retrieval. Its costs are an additional recall on each run, explicit publication and grant administration, orchestration complexity, and an accepted v1 session-history disclosure risk. Adoption requires a dedicated benchmark covering directory recall, reference integrity, routing precision, authorization filtering, ambiguity, recursive lookup, answer quality, and latency; the existing backend recall benchmark is insufficient.
